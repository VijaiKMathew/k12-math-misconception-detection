01. Pedagogical Domain & Problem Formulation

ELI25 Concept Primer: Diagnosing Student Thinking

Imagine a 7th-grade student solving the linear equation: 3x + 7 = 19. If they write 3x = 26 → x = 26/3, a naive automated grader flags the answer as incorrect. But as an expert educator or AI diagnostician, you must answer: Why did they do that?

Did they make a simple arithmetic slip (adding 7 to 19 instead of subtracting)? Did they commit a fundamental sign-inversion error when transposing across the equals sign ("pindah ruas" misconception, ALG-01)? Or did they stop at an intermediate calculation without answering the final prompt (ANS-01)?

Careless Arithmetic Slip

Mechanical addition/subtraction mistake while the underlying algebraic structure is sound (e.g. CAL-01). Usually localized to one step; student understands the operator.

Systematic Misconception

Flawed mental model applied consistently (e.g. adding fraction numerators and denominators directly: 1/2 + 1/3 = 2/5 → FRA-01). Requires targeted pedagogical remediation.

Clean Workings (NONE)

Mathematically sound execution with zero conceptual errors (root_code = NONE). Represents >45% of student traces. Any false positive error prediction destroys teacher trust.

The Evaluation Metric: Why MAP@3 Penalizes Uncertainty

The competition evaluates submissions using Mean Average Precision at 3 (MAP@3):

MAP@3 = (1 / N) ∑_{i=1}^N ∑_{k=1}^{min(3, |U_i|)} P(k) · 𝕀(y_i = ŷ_{i,k})

Because there is only one single ground truth root misconception per trace (|U_i| = 1), the scoring function collapses into a severe reciprocal rank penalty:

  • Predicted at Rank 1: 1.0000 points
  • Predicted at Rank 2: 0.5000 points (50% penalty for 1-step ordering slip)
  • Predicted at Rank 3: 0.3333 points (67% penalty)
  • Outside Top 3: 0.0000 points

This means candidate re-ranking between sibling codes (e.g., swapping KPF-01 and KPF-02) swings leaderboard scores violently. Precision at Rank 1 is the primary driver of competitive advantage.

75 Fine-Grained Codes: Misconception codes cluster into near-identical sibling pairs with identical lexical tokens—such as LCM vs GCD confusion (KPF-01 vs KPF-02) or stopping at an intermediate step vs over-answering (ANS-01 vs ANS-02). Neural bi-encoders cannot distinguish them without symbolic verification.

04. Mathematical Rigor & Proofs

Mathematical Derivations: Why Naive Blending Destroys Clean Gates

In Staff AI interviews, interviewers specifically test whether you understand the mathematical mechanics behind ensemble failure modes. Here is the exact proof of why standard probability averaging destroys the Clean Gate, and why our Max-Preserving Orthogonal Subspace Projection (𝒫⊥) is mathematically guaranteed to preserve zero false-positive drift.

Theorem 1: The Bimodal Clean Boundary Inversion Lemma

Let xi be a clean student working where true label yi = NONE. Let the anchor model output logit vector sanchor(i) ∈ ℝ76, where index 0 represents NONE and indices 1 … 75 represent misconception codes.

Because the anchor correctly classifies the trace as clean, we have:

sanchor(i, NONE) - maxc ≠ NONE sanchor(i, c) = Δi > 0

Now suppose a challenger model outputs candidate adjustments δ(i, c) ∈ ℝ for specific error codes c ∈ 𝒞err. If we apply standard linear blending with weight α > 0:

sblend(i, c) = sanchor(i, c) + α · δ(i, c)

If δ(i, c*) > (Δi / α) for any candidate c*, the argmax flips:

maxc ≠ NONE sblend(i, c) > sblend(i, NONE) ⇒ ŷblend ≠ NONE

In a dataset where 45% of examples are clean, even a 5% false-positive bleed across clean traces causes a devastating -0.0385 MAP@3 penalty across the whole test set!

Theorem 2: Max-Preserving Orthogonal Subspace Projection (𝒫⊥)

To allow challenger models to re-order candidate error codes c ∈ 𝒞err without ever flipping the clean-vs-error decision boundary, we construct the projection operator 𝒫⊥:

ŝ(i, c) = sanchor(i, c) + α · [ δ(i, c) - maxk ≠ NONE δ(i, k) ] ∀ c ≠ NONE

Proof of Invariance: By definition, the bracketed term satisfies:

maxc ≠ NONE [ δ(i, c) - maxk ≠ NONE δ(i, k) ] ≡ 0

Therefore:

maxc ≠ NONE ŝ(i, c) ≡ maxc ≠ NONE sanchor(i, c)

The maximum error logit is strictly invariant under 𝒫⊥. If the anchor predicted NONE, the ensembled prediction is guaranteed to predict NONE. The challenger model can only re-order relative ranks *within* the error subspace 𝒞err, completely eliminating clean gate degradation while boosting unclean recall!

06. Unlabelled Data Invariant Mining

The 55,000-Trace Classmate Consensus Reference Bank

We operationalized this insight by constructing a 55,000-trace Classmate Consensus Bank grouped by question_id across:

  • train.csv: 1,500 labeled traces (providing canonical ground-truth transitions)
  • test.csv: 3,498 test traces (providing question-level test distribution)
  • unlabelled.csv: 50,000 raw student traces (providing vast empirical consensus distributions)

09. Technical Forensic Audit & Red-Teaming

The Adversarial Red-Team War Story: Catching the +0.2196 Leak

This is the defining engineering achievement of this project that demonstrates Staff-level rigor. On November 12, an autonomous modeling agent submitted a report claiming a revolutionary breakthrough: CV jumped to 0.90044! Most teams would celebrate. Instead, we launched an immediate adversarial red-team audit.

Figure 4: The Leakage Trap — Why adversarial out-of-fold auditing was mandatory. Train-literal regex rules generated an artificial 0.90044 CV illusion that completely collapsed on test. Stripping every literal rule restored true honest generalization (0.68089 CV / 0.62483 LB).
🚨 Forensic Finding F1: Pure Train-Literal Memorization Leakage

Inspection of src/qaggle/verifier.py revealed that an earlier agent had authored ~202 regex rules hardcoding verbatim OCR strings from specific train.csv rows, such as: 

re.search(r"8\s*\+\s*63\s*=\s*.*?69", s)  # Hardcoded Arithmetic sequence from train row #412
re.search(r"20\s*÷\s*1\s*=\s*20.*20\s*÷\s*20\s*=\s*1", s)  # Hardcoded row #891

Because these rules matched validation fold rows during K-fold evaluation, they "predicted" the exact training label! The rules matched 18.6% of training rows, but matched only 0.09% of test rows. It was a pure in-sample memorization contest.

The Immediate Remediation Protocol

  1. Shipped Safe Gating Flag: Plumbed include_memorized_train_literals=False by default to all verifier call sites, dropping CV from the fake 0.90044 to the true honest baseline of 0.68089.
  2. Automated Invariant Scanner: Created tools/checks/check_anti_memorization.py to automatically scan every committed file for train-set OCR literal hashes, failing CI/CD builds on any detected leakage.
  3. Preserved Generalizable Grammars: Carefully preserved Section 19a generalized algebraic grammars (e.g. porogapit division columns, pindah ruas sign flips) that transfer to unseen test distributions.

The Crash: Training DeBERTa-v3 on NVIDIA Tesla T4 (Turing architecture) in standard FP16 mixed precision caused immediate NaN gradients on Step 1, silently outputting all-NaN Parquet score files.

The Staff AI Engineer Interview: 10 High-Stakes Questions & Model Answers

In Staff/Principal AI Engineer interviews at Tier-1 tech firms (Google DeepMind, OpenAI, Anthropic, Meta, Citadel), interviewers evaluate your technical depth, systems acumen, architectural trade-offs, and forensic debugging skills. Click any question to review the production-grade answer:

Q1: Walk me through your most complex debugging session. What was the hypothesis, and how did you resolve it? ▼

Context: During competitive fine-tuning of Microsoft DeBERTa-v3 on NVIDIA Tesla T4 GPUs (Turing architecture), the training loop appeared to run normally, but evaluation metrics immediately collapsed to zero, producing Parquet files filled with all-NaN values.

Root Cause Investigation: We instrumented PyTorch gradient hooks across all layers. On step 1, gradient tensors in the disentangled relative position attention module exploded to NaN. Under 16-bit floating point (FP16), the relative position score computation underflows the 16-bit exponent range before softmax normalization. While Ampere and Hopper architectures handle this via BF16, Turing lacks native BF16 arithmetic.

Engineering Resolution: We enforced strict FP32 precision for DeBERTa attention layers, replaced float("-inf") masks with -1e4 to prevent exponential underflow, and added an automated assertion assert torch.isfinite(loss) to fail-fast. This completely eliminated gradient NaN crashes.

Q2: Why not just fine-tune an end-to-end multimodal LLM like GPT-4o or Claude 3.5 Sonnet directly? ▼

The Architectural Trade-off: While frontier VLMs exhibit strong general reasoning, end-to-end prompting fails on fine-grained pedagogical K-12 math for three reasons:

  • Cost & Latency: Scoring 3,498 multi-step test images through commercial APIs costs ~$150 per submission and requires ~2.5 seconds per student. Our 5-paradigm stack executes locally in 85ms per student at zero API cost.
  • Pedagogical Taxonomy Collision: Generic LLMs cannot distinguish fine-grained Indonesian curriculum taxonomy codes (e.g. porogapit division OPS-02 vs column subtraction OPS-01) without extensive domain-specific calibration.
  • Clean Gate Calibration: Generative models hallucinate errors on sound math (clean workings). Our decoupled architecture locks clean precision at 94.25%.
Q3: How do you detect and prevent subtle data leakage in competitive machine learning pipelines? ▼

The +0.2196 Leakage Incident: An automated agent reported a CV jump from 0.74 to 0.90044. Rather than accepting the score, we cross-referenced local CV against public LB, which had slightly regressed (0.62366 → 0.62333). This divergence is a classic signature of validation leakage.

Forensic Tooling: We performed an AST audit of src/qaggle/verifier.py and found 202 hardcoded regex rules matching verbatim strings from specific training rows. We built an automated test harness (tools/checks/check_anti_memorization.py) that computes n-gram and regex coverage across train vs test splits, instantly flagging rules that match >5% of train but <0.5% of test as memorization traps.

Q4: Mathematically prove why naive probability ensembling degrades performance on bimodal distributions. ▼

Mathematical Derivation: On bimodal datasets containing clean examples (NONE) and 75 error classes, let Δi = s(i, NONE) - maxc ≠ NONE s(i, c) > 0. When ensembling a challenger model with boost δ(i, c), if δ(i, c*) > Δi / α, the argmax flips to an error code, destroying clean precision.

Solution: We derived the Max-Preserving Orthogonal Subspace Projection (𝒫⊥): subtracting the maximum candidate adjustment before addition guarantees that maxc ≠ NONE ŝ(i, c) ≡ maxc ≠ NONE sanchor(i, c), keeping clean examples mathematically invariant.

Q5: How would you scale this architecture to serve 10 million students with sub-150ms latency? ▼

Production Architecture:

  • Tier 1 Gate (<10ms): Lightweight MobileNet-v4 edge classifier routes clean workings (NONE) immediately, bypassing heavy neural models for 45% of traffic.
  • Tier 2 Retrieval (<30ms): TensorRT-optimized BGE-M3 bi-encoder queries an in-memory vector index (Milvus/FAISS) of the 55k Classmate Consensus Bank.
  • Tier 3 Symbolic Engine (<15ms): Rust/C++ compiled AST algebraic state transition engine evaluates Lk-1 → Lk equivalence on CPU cores.
  • Tier 4 Cross-Scoring (<50ms): Quantized ONNX DeBERTa-v3 reranks top 5 candidate codes via GPU batching.

Total P99 latency: 105ms at an estimated infrastructure cost of <$0.0001 per student query.

Q6: How did you handle 100% missing step transcriptions in the test set? ▼

In train.csv, step-by-step transcriptions were annotated by human experts, but test.csv contained only raw images. Competitors who trained NLP models on ground-truth transcriptions suffered catastrophic test collapse.

We solved this by training an OCR-invariant bridge: we extracted pseudo-transcriptions using fine-tuned Qwen2.5-VL and mapped each test trace to the Classmate Consensus Reference Bank via question_id, synthesizing canonical step transitions without relying on manual test annotations.

Q7: Explain the loss function used for P3 (Process-Supervised Step Cross-Encoder). ▼

Standard cross-entropy loss over a shuffled batch introduces global prior bias, unfairly penalizing rare topics. Instead, we implemented Trace-Grouped ListNet with Intra-Trace Margin Ranking Loss:

L(i) = ∑_{c \in C_i} -P_{ ext{true}}(c) \log P_{ ext{pred}}(c) + \lambda \max(0, m - s(i, c_{ ext{root}}) + s(i, c_{ ext{secondary}}))

Crucially, the margin loss is computed strictly within the candidate pool of a single trace_id, forcing the model to separate the primary root cause from secondary procedural slips.

Q8: Why choose Tailscale WireGuard over traditional ngrok or reverse proxies for cloud compute? ▼

During long 8-hour QLoRA training runs on Google Colab, free-tier reverse proxies like ngrok and Cloudflare Quick Tunnels frequently disconnect (ngrok bandwidth throttling ERR_NGROK_725, Cloudflare 502 Bad Gateway). When the tunnel drops, unattended training scripts lose their monitoring socket.

Tailscale creates an authenticated, kernel-level WireGuard mesh network. The Colab node receives a static private IP (100.x.y.z) accessible directly from our workstation with zero port forwarding, end-to-end encryption, and seamless auto-reconnect across IP renegotiations.

Q9: How do you formulate the Unitary Horizon Expansion (ℋ24)? ▼

Early pipelines took only the top 8 candidates from a single vision model, creating a hard recall ceiling of 79.16% on unclean workings. To break this ceiling, we constructed a 24-candidate unitary union across 5 discovery channels:

ℋ24 = Top8(P1 VLM) ∪ Top10(P2 BGE-M3) ∪ Top5(Question Empirical Prior) ∪ Top3(Symbolic Verifier AST) ∪ Top3(Verbatim Step Diff).

This raised candidate pool recall to 92.29% on unclean workings and 94.60% overall, providing an expanded search subspace for downstream listwise rerankers.

Failed Approach: Running Qwen2.5-Math on test data.
Why It Failed: 100% of test rows lack step transcriptions. The model hallucinated student steps from question prompts, regressing CV by -0.0520.

2. Unconstrained Blending

Failed Approach: Softmax probability averaging.
Why It Failed: Shifted maximum error logit above clean threshold, causing clean student workings to flip into errors (-0.0385 MAP@3).

3. Kaggle TPU torch_xla

Failed Approach: Distributed training on Kaggle TPU v3-8.
Why It Failed: Incompatible ABI between PyTorch 2.11 and torch_xla wheels in Nov 2026. Pivoted to Colab Tesla T4.

4. Permissive Train Regexes

Failed Approach: Authoring regexes matching train OCR.
Why It Failed: Matched 18.6% of train but only 0.09% of test. Pure in-sample leak creating false 0.90044 CV illusion.

5. In-Sample SFT Fitting

Failed Approach: Scoring all 1,500 train rows with whole-dataset adapter.
Why It Failed: Stacker coordinate ascent overfit in-sample scores, causing v4.3 LB regression (0.61283).

6. Raw Levenshtein OCR

Failed Approach: String edit distance against taxonomy.
Why It Failed: Student handwriting OCR noise produced meaningless edit distances; replaced with dense BGE-M3 bi-encoders.
